# Module: Agent Proxy

- Статус: **Спроектирован, ожидает реализации** (Hermes-интеграция)
- Ответственность: контур `/v1/agent/*` — прокси чата к персональному Hermes-инстансу пользователя (`POST /v1/runs`), ретрансляция SSE-событий на iOS, policy-gate до прогона, биллинг по реальному usage на `run.completed`. Headline-фича сервиса (автономный агент). Простой чат `/v1/chat/*` остаётся отдельно.

## DoD
- `POST /v1/agent/run` — auth ([ADR-044](../../adr/ADR-044-client-api-key-auth.md)) → policy-gate (BR-2/3/5, [ADR-002](../../adr/ADR-002-access-policy-state-machine.md)) → `ensure_running(userId)` ([ADR-046](../../adr/ADR-046-per-user-hermes-runtime.md)) → прокси `POST {base}/v1/runs` (`Authorization: Bearer <API_SERVER_KEY>`) → `202 {runId, status}`. Blocked → `200 {status:blocked, blockReason}` ([ADR-004](../../adr/ADR-004-blocked-http-200.md)).
- `GET /v1/agent/runs/{runId}/events` — SSE-ретрансляция из Hermes; на `run.completed{usage}` → `WalletService.consume(idempotency_key=runId)` (конвертация токенов в кредиты, [ADR-047](../../adr/ADR-047-usage-based-billing-for-agent.md)); `run.failed` → без debit.
- `POST /v1/agent/runs/{runId}/approval`, `POST /v1/agent/runs/{runId}/stop` — passthrough к Hermes.
- **([ADR-064](../../adr/ADR-064-incremental-agent-run-billing-and-pause-resume.md), под флагом `agent_incremental_billing_enabled`)** incremental-биллинг на `usage.delta` (idempotency `runId:step`, cumulative-owed-minus-charged, seed из ledger); pause-at-zero → `run.paused` без долга; финализация остатка на `run.completed` (idempotency `runId`).
- **`POST /v1/agent/runs/{runId}/resume`** ([ADR-064 §5](../../adr/ADR-064-incremental-agent-run-billing-and-pause-resume.md)) — RBAC-404, пред-гвард `status∈{paused,resumed}`→409 `run_not_resumable`, policy-gate (blocked 200), **атомарный CAS `paused→resumed`** (арбитр гонки: конкурентные resume/ретраи → один child; проигравший→active child или `409 resume_in_progress`), hydrate→`conversation_history` (`404`/пусто → `409 session_expired`, откат CAS), `_launch_run` **после** CAS (single-flight)+chain (`agent_runs`), `202 {status:running, runId:new, continuedFrom:old}`.
- **`GET /v1/agent/runs/{runId}/state`** ([ADR-066](../../adr/ADR-066-agent-run-state-snapshot.md)) — снапшот состояния прогона из БД (`agent_runs` + новая `agent_run_snapshots`, миграция `0019`): `{runId, sessionId, status, resultText, lastTool, pendingApproval, blockReason, usage, updatedAt, continuedFrom}`. **Строго read-only** (без `ensure_running`/Hermes/списаний/policy-gate), RBAC-404, `429` по rate-limit. Снапшот пишется **побочным эффектом relay** `/events` (троттлинг `message.delta`, **per-column** replay-guard: длина текста + `GREATEST` по токенам + `pending_approval` через `CASE WHEN :assert_approval` (троттлинговый `message.delta` его не трогает) при безусловных `last_tool`/`updated_at`, head-preserving truncation). Статус `waiting_approval` — производный (`running|resumed` + `pending_approval`), `cancelled` → клиентский `stopped`.
- **Lifecycle-запись `agent_runs` — всегда** ([ADR-066 §3](../../adr/ADR-066-agent-run-state-snapshot.md)): `create_running`/терминальный статус пишутся независимо от `agent_incremental_billing_enabled` (под флагом — только биллинг). Терминальный статус пишет сервисный `_mark_terminal(run_id, status)` (обёртка над репозиторным `mark_status`, commit + проглатывание `SQLAlchemyError`) **до** биллинга и независимо от его исхода (отказ списания больше не оставляет прогон вечно `running`); `mark_stopped(run_id, user_id)` и `clear_pending_approval(run_id, user_id)` — owner-scoped. Начинают выставляться `failed` (на `run.failed`) и `cancelled` (после 2xx клиентского `POST /stop`) — ранее не записывались никогда. **Все** переходы статуса условные (`WHERE status IN ('running','resumed')`), `mark_stopped(run_id, user_id)` — только клиентский путь (внутренний interrupt pause-at-zero статус не помечает).
- **Открытые вопросы фичи:** [Q-066-1](../../99-open-questions.md) (семантика replay Hermes — префиксный guard корректен при любой), [Q-066-2](../../99-open-questions.md) (глобальная уникальность `run_id` + tenancy-гвард), [Q-066-3](../../99-open-questions.md) (`continuedTo` parent→child).
- **Retention** снапшота — `AGENT_RUN_SNAPSHOT_TTL_DAYS` (14): у терминальных прогонов чистится только `result_text`/`pending_approval`, строка и `/state` остаются; sweep идемпотентен и `updated_at` не двигает.
- Маппинг тела `message→input`, `sessionId→session_id`, `model→model`; `effective_session_id = sessionId or uuid4()` пишется в `agent_runs`.
- `/v1/chat/*` не затронут; Hermes в `LLMClient.create_message` не заводится.
